# Начин ERP

Талх, нарийн боов, кофе, хоол үйлдвэрлэлийн компанийн дотоод удирдлагын
энгийн систем. Өдөр тутмын борлуулалт бүртгэхэд жорын дагуу түүхий эд
автоматаар хасагдаж, жигнэсэн дундаж өртгөөр өртөг тооцоологдоно.

## Технологи

Next.js 15 (App Router) · TypeScript · PostgreSQL · Prisma · Tailwind CSS ·
Zod. Нэг л апп — микросервис ашиглаагүй.

## Хурдан эхлэх

```bash
cd apps/web
cp .env.example .env          # DATABASE_URL-ээ тохируулна
npm install
npx prisma migrate deploy     # хөгжүүлэлтэд: npx prisma migrate dev
npm run db:seed               # жишээ өгөгдөл
npm run dev
```

Жишээ хэрэглэгчид (seed):

| Эрх     | И-мэйл                | Нууц үг        |
| ------- | --------------------- | -------------- |
| Эзэн    | owner@example.com     | `Password123!` |
| Менежер | manager@example.com   | `Password123!` |

## Архитектур

```
src/
  app/
    login/            нэвтрэх
    (app)/            хамгаалагдсан хэсэг — sidebar-тай layout
      dashboard/ materials/ products/ purchases/ sales/
      expenses/ counts/ money/ reports/ audit/ settings/
        actions.ts    server action-ууд (Zod шалгалт + эрх + сервис дуудлага)
  components/         дахин ашиглагдах UI (Card, Table, Modal, Field, ...)
  lib/                prisma, decimal, units, dates, format, audit, validation
  server/services/    домэйны логик — inventory, purchases, sales, counts,
                      expenses, money, adjustments, recipes, reports, dashboard
```

Бизнес логик React компонент дотор биш, `src/server/services/` дотор байна:
`postPurchase()`, `postSalesBatch()`, `calculateWeightedAverageCost()`,
`applyMovement()`, `finalizeInventoryCount()`, `postBankDeposit()`,
`cancelPurchase()`, `cancelSaleBatch()`.

## Тогтмол баримтлах дүрмүүд

1. **Нөөцийн өөрчлөлт бүр `InventoryMovement` үүсгэнэ.**
   `RawMaterial.quantity` / `averageCost`-ыг `applyMovement()`-оос гадуур
   хэзээ ч шууд өөрчлөхгүй.
2. **Мөнгөний өөрчлөлт бүр `MoneyTransaction` үүсгэнэ.** Касс, банкны
   үлдэгдлийг гараар засахгүй — дэвтрээс тооцоологдоно.
3. **Чухал үйлдэл бүр аудитад бүртгэгдэнэ.**
4. **Худалдан авалт жигнэсэн дундаж өртгийг шинэчилнэ:**
   `(хуучинТоо × хуучинДундаж + шинэТоо × шинэӨртөг) / (хуучинТоо + шинэТоо)`.
5. **Түүхэн өртөг өөрчлөгдөхгүй.** Борлуулалтын үеийн өртөг
   `SaleItem.unitCost` болон `InventoryMovement.unitCost` дээр царцана.
6. **Борлуулалт жорын дагуу материалыг автоматаар хасна.**
7. **Санхүүгийн бичлэгийг устгахгүй** — `CANCELLED` төлөв + эсрэг бичилт.
8. **Сөрөг үлдэгдэл анхдагчаар хориотой.** Эзэн тохиргоогоор нээж болно.
9. Критик үйлдэл бүр **нэг өгөгдлийн сангийн гүйлгээнд** гүйцэтгэгдэнэ.

`npm run verify` эдгээр дүрмийг дэвтрүүдээс дахин тооцож шалгана.

## Хэмжих нэгж

Материал бүр ганц үндсэн нэгжтэй (`RawMaterial.unit`) — нөөц, өртөг, жор
бүгд түүгээр илэрхийлэгдэнэ. Худалдан авалт болон жор нь нийцтэй нэгжээр
бичигдэж, автоматаар хөрвүүлэгдэнэ:

* Жин: кг ↔ гр
* Эзэлхүүн: л ↔ мл
* Ширхэг: ш / хайрцаг / багц — хооронд хөрвөхгүй

## Хойшид нэмэх боломжтой (одоо хийгээгүй)

Салбар, олон агуулах, нийлүүлэгчийн гэрээ, худалдан авалтын захиалга,
POS API импорт (`SaleBatch.source` талбар бэлэн), баркод, үйлдвэрлэлийн
багц, хаягдлын удирдлага. Одоогийн хувилбар нэг компани, нэг агуулахад
зориулагдсан.
